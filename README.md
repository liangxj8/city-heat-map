# 国庆去哪儿 · 全国城市热度地图

一个**纯静态、零构建、可离线**的交互式数据新闻页面：把小红书上那张《国庆假期，哪儿人少？》的静态长图，做成了能**缩放、hover、点击、筛选**的可交互地图。

共收录 **355 个城市 / 目的地**（全国地级行政区 + 直辖市 + 港澳 + 台湾主要目的地），覆盖 **34 个省级行政区**（含台湾省、香港特别行政区、澳门特别行政区）。

热度指数不再是估算值 —— 它等于 **2025 年国庆假期（10 月 1 日 — 10 月 7 日）日均人口迁入规模指数**，来自 **百度迁徙（百度地图慧眼）**，经归一化映射到 0–100；行政区划、经纬度与底图边界来自 **阿里云 DataV.GeoAtlas**。抓取脚本见 `tools/fetch-real-data.js`。

---

## 一、如何打开

> **双击 `index.html` 即可。**

- 不需要启动服务器，不需要联网，不需要 `npm install`，不需要任何构建步骤。
- 因为页面要支持 `file://` 协议直接打开，**所有数据都以本地 `.js` 文件的形式引入**（`window.CHINA_GEO` / `window.CITIES`），代码中**没有任何 `fetch()` / `XMLHttpRequest`**（`file://` 下会被浏览器 CORS 拦截）。
- 所有依赖（ECharts 5.5.1、地图边界、城市数据）都在本地，断网也能正常用。

如果你想用本地服务器预览（可选）：

```bash
# 任选一种
npx --yes http-server -p 8080
python -m http.server 8080
```

浏览器要求：Chrome / Edge / Firefox / Safari 近两年版本均可（用到了 `Element.closest()`、`Array.prototype.some()`、CSS Grid）。

## 四、如何替换成你自己的数据

只需要改 **`data/cities.js`** 里的 `CITY_RAW` 数组，**一行一个目的地**，其它文件都不用动。

### 4.1 元组格式

```js
var CITY_RAW = [
  ["杭州", "浙江", 120.15, 30.29, 100, 2.2,
   ["西湖", "热门打卡", "自然风光"],
   "西湖断桥人从众，灵隐与西溪都需要预约。",
   "清晨六点环西湖骑行，灵隐抢最早场。",
   "3天",
   ["西湖", "灵隐寺", "西溪湿地", "良渚古城"], "real", 15.497],
  // ... 继续追加
];
```

### 4.2 字段含义

| 下标 | 字段名 | 类型 | 说明 |
| --- | --- | --- | --- |
| 0 | `name` | string | 城市 / 目的地名称，**全表唯一**（自检脚本会查重） |
| 1 | `province` | string | 省级行政区**简称**，必须命中下表 34 个之一 |
| 2 | `lng` | number | 中心经度（DataV 提供），范围 73–136 |
| 3 | `lat` | number | 中心纬度（DataV 提供），范围 3–54 |
| 4 | `heat` | number | **国庆热度指数**，0–100 整数，越高越挤（由真实迁入规模指数归一化得到） |
| 5 | `delta` | number | **真实同比**：2025 国庆日均迁入指数 − 2024 国庆日均迁入指数，一位小数，正=更挤 |
| 6 | `tags` | string[] | 标签数组，用于快捷筛选匹配 |
| 7 | `reason` | string | 一句话说明国庆去这里的体验 / 拥挤情况 |
| 8 | `tip` | string | 一句话实用建议（错峰时间、交通、住宿） |
| 9 | `days` | string | 建议游玩天数，如 `"2-3天"` |
| 10 | `spots` | string[] | 代表景点，**2–4 个** |
| 11 | `src` | string | 热度来源：`real` 本市真实数据 / `province` 省级汇总 / `median` 同级中位数兜底 |
| 12 | `raw` | number | **原始迁入规模指数**（2025 国庆 7 天日均，3 位小数，未归一化），用于并列热度时排序与 tooltip / 详情展示 |

> `crowd` 字段**不需要手写** —— 脚本末尾会自动按 `heat` 推导并补齐：
> `≥85 爆满 / 70–84 拥挤 / 50–69 适中 / 30–49 舒适 / <30 冷清`。
> 这样设计是为了保证 `crowd` 与 `heat` 永远一致，不会手抄出错。
>
> 最终对外暴露的是标准对象数组 `window.CITIES`，字段与需求文档完全一致。

### 4.3 省级行政区简称（必须严格一致）

```
北京 天津 河北 山西 内蒙古 辽宁 吉林 黑龙江 上海 江苏 浙江 安徽
福建 江西 山东 河南 湖北 湖南 广东 广西 海南 重庆 四川 贵州
云南 西藏 陕西 甘肃 青海 宁夏 新疆 台湾 香港 澳门
```

简称与 GeoJSON 全称的映射表在 `assets/app.js` 顶部的 `PROVINCE_FULL_NAME` 常量里，如需改名请两处同步。

### 4.4 换完数据后，务必跑一次自检

```bash
node tools/selfcheck.js
```

它会检查：条数 ≥ 320、34 省全覆盖、字段完整性、`heat` 是 0–100 整数、`crowd` 与 `heat` 一致、经纬度在中国范围内、景点数 2–4 个、城市名不重复、省份简称能映射到 GeoJSON、`app.js` 引用的 DOM id 在 `index.html` 中全部存在、代码中没有 `fetch()` / `XMLHttpRequest`。

### 4.5 想换地图边界数据

替换 `data/china_full.json`（保持标准 GeoJSON FeatureCollection，`properties.name` 为省级全称），然后执行：

```bash

```

**不要直接编辑 `data/geo.js`**，它是自动生成物（文件头有标注）。

## 五、真实数据源

### 5.1 数据从哪来

| 用途 | 数据源 | 接口 |
| --- | --- | --- |
| 城市清单 / adcode / 经纬度 | 阿里云 **DataV.GeoAtlas**（民政部行政区划标准） | `https://geo.datav.aliyun.com/areas_v3/bound/{省adcode}_full.json` |
| 热度（人流） | **百度迁徙**（百度地图慧眼）迁入规模指数 | `https://huiyan.baidu.com/migration/historycurve.jsonp?dt=city&id={adcode}&type=move_in` |
| 底图边界 | 阿里云 **DataV.GeoAtlas** | 见「六、底图数据来源与合规标注」 |

抓取脚本：**`tools/fetch-real-data.js`**（Node 内置 `https`，零第三方依赖）。

```bash
node tools/fetch-real-data.js            # 正常跑（命中缓存则跳过已抓过的城市）
node tools/fetch-real-data.js --force    # 忽略百度缓存，全部重新抓取
node tools/fetch-real-data.js --dry      # 只跑城市清单，不抓百度（调试用）
```

脚本流程：

1. 遍历 34 个省级 adcode，从 DataV 取各地级行政区（`adcode` / `name` / `center`）；直辖市（北京、天津、上海、重庆）与港澳按「一个行政区 = 一个城市」处理；台湾省 DataV 无数据，使用内置清单并用百度省级（710000）指数。
2. 对每个城市调百度迁徙 `historycurve`，取 **2025-10-01 ~ 10-07** 与 **2024-10-01 ~ 10-07** 两段日均迁入规模指数（不足 4 天视为无数据）。
3. 归一化成 0–100 的 `heat`，计算同比 `delta`。
4. 按城市名匹配复用人工撰写的 `tags / reason / tip / days / spots`（匹配不到则按热度等级生成合理默认值，不留空）。
5. 写出 `data/cities.js`（保持 `window.CITIES` 全局变量格式，`assets/app.js` 无需改动）。

### 5.2 字段口径

- **`heat`（0–100 整数）** = 2025 年国庆假期（10.1–10.7）**日均人口迁入规模指数**归一化后的值，越高代表假期迁入人流越集中、越挤。
  归一化采用**对数归一化 + p2/p98 分位截断**：

  ```
  heat = round( 100 * (ln(v) − ln(p2)) / (ln(p98) − ln(p2)) )   并截断到 [0, 100]
  ```

  迁入规模指数是典型长尾分布（本数据集实测 0.003 ~ 21.4，跨度近 4 个数量级）：直接线性映射会让 90% 的城市挤在 0–10 分；取对数后可拉开中小城市之间的区分度；上下各截掉 2% 分位，避免三沙（0.003）等极小值和成都、广州等极值把区间拉变形。
  脚本会同时计算「对数归一化」与「百分位映射」两套方案并比较五档分布，自动挑选分布更合理的一套（本次选中的是对数归一化，p2 = 0.050、p98 = 14.211）。

- **`raw`（三位小数）** = 未归一化的原始迁入规模指数，随数据一起落盘。它的两个作用：
  1. **打破并列**：归一化在 p98 处做了截断，原始指数 ≥ 14.211 的 12 个城市 `heat` 都是 100 分。`assets/app.js` 的 `sortByHeat()` 在 `heat` 相同时**改用 `raw` 排序**（降序榜按 raw 降序、升序榜按 raw 升序），所以「最挤 TOP1」是真实的成都（21.434），而不是按纬度碰巧排到的城市。
  2. **展示可信度**：tooltip 与详情面板会显示「原始迁入规模指数 21.43（全国第 1）」，让用户直观看到 heat 是真实指数换算来的，也解释了为什么多个城市同为 100 分。

- **`delta`（一位小数）** = 2025 年国庆日均指数 − 2024 年国庆日均指数，是**真实同比**，不是百分点估算。正值 = 比去年更挤。
- **`src`**：`real`（本市真实数据，349 个）/ `province`（省级汇总，台湾省 6 个）/ `median`（同级中位数兜底，本次 0 个）。

### 5.3 缓存与重跑

- 原始响应按 adcode 缓存在 `data/.cache/`：`datav_{省adcode}.json`、`mig_{城市adcode}.json`。
- 已缓存的城市**不再发起请求**，中断后重跑会自动续上；`--force` 可强制刷新。
- 请求间隔 350 ms，单城市失败重试 2 次，仍失败会进「失败清单」并在结尾汇总打印；每 50 个城市打印一次进度。
- 完全拿不到真实数据的城市：先用**本省中位数**兜底，全省都无数据则用**全国中位数**，`src` 标记为 `median`，不会崩、不会留空。
- **地图合规**：台湾省、香港特别行政区、澳门特别行政区无论有无数据都会保留在底图与数据集中（港澳有真实数据；台湾各地使用省级汇总指数并在文案中明确标注覆盖有限）。
- **榜单排序**：`src === 'province'`（省级汇总）的城市**默认不参与「最挤 / 最舒服 TOP20」排名**，因为该口径与大陆城市不完全可比；但地图散点、hover tooltip、点击详情、省份 / 热度 / 标签筛选、搜索**全部照常**，只有当筛选结果里**只剩下**这类城市时（例如省份筛选选了「台湾省」）榜单才会显示它们，并附一行口径提示。三沙（真实指数 0.003 → heat 0）是真实数据、不是缺失，正常参与排名。

## 五·补、三峡专题点位（奉节 / 巫山 / 巴东 / 秭归）

这四个是长江三峡沿线的**县级**行政区。百度迁徙的最小粒度是**地级行政区**，拿不到它们的迁徙数据（实测 `historycurve?dt=city&id=500236` 等四个 adcode 均返回空；`dt=district` 报 `dt is not valid`；连重庆的万州、黔江、涪陵这类「区」同样为空）。

因此改用**地方政府官方发布的 2025 年国庆假日旅游统计**。

### 为什么不做统一折算

**这四个数字口径互不相同，彼此不可比**，而且没有任何单一口径是四县齐全的：

- 巫山 96.75 万是「全县接待」（含探亲、过路、非景区访客），奉节 22.73 万只是「景区购票」——
  两者相差 4 倍**纯粹是口径差异，不是真实热度差距**。
- 景区购票口径缺巴东；全县接待口径缺奉节、秭归。

强行折算成一个「可比热度值」只会制造虚假的精确性，因此这里的处理是：

1. 四个县**照常上图**，可 hover、点击、搜索、按省份筛选；
2. tooltip 与详情展示**官方原始数值 + 明确的口径标注 + 数据来源**；
3. **不显示**「国庆热度指数」（它们的 `heat` 只是供散点渲染的中性占位值 50）；
4. **不参与**全国热度榜单排名，也**不参与**统计卡的「最挤 / 最舒服」极值计算；
5. 用**菱形 + 专题色**渲染，视觉上区别于常规城市（独立 series `sanxiaScatter`，不被 `visualMap` 着色）。

> 如需新增同类型专题点位：在 `tools/fetch-real-data.js` 的 `SANXIA_OFFICIAL` 常量里追加，
> 填入官方数值与**准确的统计口径**，重跑脚本即可。切勿为了让它们「看起来能比较」而编造或折算数值。

## 六、底图数据来源与合规标注

- **边界数据**：阿里云 **DataV.GeoAtlas**（`https://geo.datav.aliyun.com/areas_v3/bound/100000_full.json`），基于**民政部行政区划标准**。
- 数据包含 **35 个要素**：34 个省级行政区 + **南海诸岛**。
- **台湾省、香港特别行政区、澳门特别行政区、南海诸岛均作为中国领土的一部分完整呈现**，在地图中与其它省级行政区同级渲染，不做任何单独标注或区别对待。
- 本页面**不使用** Google Maps / OSM / Mapbox / Leaflet 等任何第三方地图瓦片服务，底图完全由 ECharts `registerMap` + 本地 GeoJSON 自绘。

## 七、技术实现要点

| 约束 | 做法 |
| --- | --- |
| `file://` 下不能用 `fetch()` | 边界与城市数据全部转成 `window.*` 全局变量的 `.js` 文件，用 `<script src>` 引入 |
| 不能引入 CDN | ECharts 5.5.1 落到本地 `assets/echarts.min.js` |
| 视图切换要平滑，且残留的 `geo.regions` 要清干净 | 两种视图**共用同一个 `geo` 组件**（省份填充用 `geo.regions` 着色，不用 `map` series），因此散点始终与底图坐标系同步；仅当视图真正切换时才用 `setOption(opt, {replaceMerge: ['geo','series']})`，其余一律增量 `setOption` 走动画过渡 |
| 缩放后不能因为重绘被拉回 | 监听 `georoam` 事件，把当前 `center` / `zoom` 同步回 `state`，每次 `setOption` 时原样带回 |
| `crowd` 与 `heat` 必须一致 | 由脚本统一推导，不手写 |
| 无构建工具 | 原生 ES5 语法 + IIFE，浏览器直开 |
